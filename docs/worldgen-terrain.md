# Terrain: how a pixel becomes a material

The per-pixel pass. `ProceduralTerrain::GetMaterialAt` (`0x0087d0e0`) is called once for each of
a chunk's 262144 cells and returns a `CellMaterial*` (or nothing, for air). This page covers its
three branches, the cave generator behind the procedural branch, the ore-selection algorithm,
how the result is stored, and the spawn requests collected alongside.

Biome fields: [worldgen-biomes.md](worldgen-biomes.md). Tile system:
[worldgen-wang.md](worldgen-wang.md).

## The dispatcher

```c
// 0x0087d0e0, simplified
biome = resolve_biome(x, y);                       // 0x0087d9a0
if (!biome) return NULL;
switch (biome->type) {
  case BIOME_PROCEDURAL:
      shape_cave_noise(biome, x, y);               // 0x0087e110 -> v
      return select_material(biome->materials, x, y, v);   // 0x0086d2a0

  case BIOME_BITMAP:
      u = ((x % bmp->w) + bmp->w) % bmp->w;        // wraps in both axes
      w = ((y % bmp->h) + bmp->h) % bmp->h;
      value = bmp->data[bmp->w * w + u];           // packed RGBA, no interpolation
      if ((value & 0xffffff) == 0) return NULL;    // black = air
      return material_by_colour(value);            // 0x004ad000

  case BIOME_WANG_TILE:
      tile = wang_tile_at(biome->wangmap, x, y);   // 0x008712d0
      material = tile >= 1 ? material_by_index(tile) : NULL;
      if (!material) goto procedural;              // gaps fall back to the procedural path
      if (x_in_tiles < material->threshold) return NULL;   // CellMaterial+0x238
      return material;
}
```

- **Bitmap biomes tile.** `bitmap_filename` repeats in both axes; there is no scaling or
  interpolation. Black (RGB 0) is air; any other colour is looked up as a material colour.
- **Wang biomes fall back to procedural.** A pixel whose wang lookup yields no tile, or a tile
  that is not a known material, is generated by the procedural path instead. A sparse template
  produces procedural terrain in its gaps rather than holes.
- **A per-material threshold can turn a wang tile into air.** `CellMaterial + 0x238` (a float,
  default `0.5`) is compared with the pixel's x in wang-tile units (`x/10 + 0.05`); below it the
  pixel is air. Two neighbouring material fields feed the same step: `+0x234` (default `1.0`) is
  a noise-blend amount and `+0x23C` (default `0`) selects one of three tile-shape helpers. Neither
  is settable from `materials.xml`.

Material handles are array indices: `CellMaterial* = base + index * 0x290`.

## Type 0: procedural, and the material selector

Two stages: `0x0087e110` computes a scalar **cave value** `v` for the pixel, and `0x0086d2a0`
turns `v` into a material using the biome's `<MaterialComponent>` list. The selector decides what
everything is made of, so here it is in full:

```c
// 0x0086d2a0, restructured
if (!(aggregate_min <= v && v <= aggregate_max)) return NULL;   // union of all components' ranges

for (rec in components, sorted by material_index ascending) {
    if (rec->limit_y && !(rec->limit_min_y <= y && y <= rec->limit_max_y)) continue;

    if (rec->is_polygon) {
        px = hash(x, 512) / 512.0;  py = hash(y, 512) / 512.0;   // -> [0,1]
        if (!point_in_polygon(px, py, rec->polygon)) continue;
    }
    if (!rec->material) continue;

    t = v;
    if (rec->add_perlin) t += perlin(x * rec->add_perlin_scale_x, 0);

    if (!(rec->material_min <= t && t < rec->material_max)) continue;
    if (!rec->is_rare) return rec->material;

    rx = rec->rare_offset_x + x * rec->rare_scale_x;
    ry = rec->rare_offset_y + y * rec->rare_scale_y;
    if (rec->rare_offset_by_seed) { rx += world_seed * K1; ry += world_seed * K2; }

    if (rec->rare_use_perlin) {
        g = rec->rare_use_fbm_perlin ? fbm_perlin(rx, ry) : perlin(rx, ry);
        if (!(rec->rare_required_min < g && g <= rec->rare_required_max)) continue;
    }
    if (!rec->rare_use_polka) return rec->material;
    p = polka(rx, ry, rec);                                      // (1 - d^2)^3 dots
    if (rec->rare_required_min < p && p <= rec->rare_required_max) return rec->material;
}
return NULL;   // air
```

What this means when writing an ore list:

- **`material_index` is the priority, and lower wins.** The list is sorted once at load by
  `material_index`; XML order does not matter. The first component whose gates all pass claims the
  pixel. A component that fails a gate leaves the pixel to the next one.
- **Two different quantities are banded.** `limit_min_y`/`limit_max_y` band the integer pixel
  **y**. `material_min`/`material_max` band the **cave value** (a float).
- **`is_rare="0"` (the default) skips all the `rare_*` gates.** The component returns its
  material as soon as the value range matches.
- **`is_rare="1"` with default settings is very selective.** The perlin is scaled to roughly
  ±70, so only a sliver falls in the default window `(0.2, 1.0]`; the polka function is 0 almost
  everywhere, so `p > 0.2` keeps only the dot cores. Shipped ores tune `rare_required_min` (e.g.
  `0.371429`) for this reason. "Rare" means rare within the value band, not rare globally.
- **Both rare gates use the same window**, exclusive below and inclusive above:
  `rare_required_min < g <= rare_required_max`.
- **`add_perlin` is one-dimensional**: `perlin(x * add_perlin_scale_x, 0)`. `add_perlin_scale_y`
  is parsed but has no effect.
- **`rare_scale_*` / `rare_offset_*`** place and stretch the ore pattern independently of the
  cave shape. A `rare_scale` of `0.0214286` gives blobs about 47 px across.
- **`rare_offset_by_seed`** shifts the pattern by the world seed, so ore moves between runs.
- **Polka dots** are periodic blobs with a radius between `rare_polka_radius_low` and
  `rare_polka_radius_high`, optionally boxed to squares (`rare_polka_is_boxed`), scaled by
  `rare_polka_probability`.

### `is_polygon`

With `is_polygon` set, a component also requires the pixel to fall inside `polygon` (points in
`[0,1] x [0,1]`). The pixel's x and y are each hashed onto a 512 grid and scaled into the unit
square, then tested with a crossing-number algorithm. Four shipped biomes use it: `boss_arena`,
`end_wall`, `lava_90percent`, `temple_wall`.

## Procedural noise shaping

`0x0087e110` produces the cave value `v` for a procedural biome:

1. Convert the world pixel into wang-map space and read the biome's cave map (below), blending
   toward the surface.
2. If `v > 0.5` and `mMultiplierPerlin` is non-zero, apply a blob-cave step to the remapped
   value `(v - 0.5) * 2`.
3. Apply the noise selected by `noise_type`: `IQ2_SIMPLEX1234` (default), `IQ_SIMPLEX`,
   `SIN_CAPPED_EVERYTHING` or `SIN_CAPPED_SIMPLEX` (the last two built from `sin`/`cos`).

The gradient fields set the two ends of the value range at a pixel: `mGradientStartY` and
`mGradientEndY` (`-512.0`, `512.0`). `mGradientAddNoise` selects how they are perturbed:

| `mGradientAddNoise` | effect |
|---|---|
| 1 (default) | perlin noise added to both ends |
| 2 | fbm perlin on the first end |
| 3 | both ends shifted by `(y - mGradientSlopeStartX) * mGradientSlopeDelta` - a linear ramp |

Noise terms are scaled by `mGradientNoiseScale` (`0.01`) and bounded by `mGradientLowNoise` /
`mGradientHighNoise` (`-100.0` / `100.0`).

## The cave generator: `<BitmapCaves>`

`<BitmapCaves>` describes how many caves, blobs and mountains to carve and how strongly; the
shapes themselves are perlin. The descriptions in quotes are the game's own.

| field | default | meaning |
|---|---|---|
| `name` | `""` | cache key: biomes with the same `name` share one carved map |
| `size_x` | `512` | "How big the image is that we generate these from" |
| `size_y` | `256` | |
| `spawn_percent` | `0.05` | "0-1 - with what chance do we add a spawn point to a cave" |
| `cave_count_min` / `_max` | `50` / `100` | number of caves |
| `do_beginning_paths` | `false` | "the paths that go down near the center of the image, used for setting up the caves to coal mines near where player starts" |
| `do_beginning_down` | `false` | "a hole straight down" |
| `surface_caves_count_min` / `_max` | `7` / `12` | caves starting at the surface |
| `cave_strength_min` / `_max` | `0.2` / `1.0` | "how strongly do we carve the cave" |
| `cave_childs_min` / `_max` | `0` / `2` | "how many child trails a cave can have" |
| `surface_cave_childs_min` / `_max` | `2` / `7` | |
| `mountain_count_min` / `_max` | `0` / `15` | |
| `mountain_size_min` / `_max` | `1.0` / `10.0` | |
| `blob_caves_count_min` / `_max` | `20` / `55` | |
| `blob_caves_strength_min` / `_max` | `1.5` / `3.0` | |
| `blob_caves_radius_min` / `_max` | `1.0` / `10.0` | |
| `structures` | empty | list of `<CaveStructure>` |
| `mLuaScript` | `""` | "we share these based on the names, so make them unique" |
| `DEBUG_output_image` | `""` | "if set, will save a png of the height map to the file specified here" |

The defaults describe a large cave system (50-100 caves, 20-55 blobs, up to 15 mountains on a
512 x 256 field). `coalmine.xml` cuts almost all of it down - 2 caves, no blobs - because a wang
biome gets its shape from the template; only its `CaveStructure` stamps remain.

**The output is a wang map, not an image.** Caves are written into the biome's wang-map planes
(`mBitmapNoise`, see [worldgen-wang.md](worldgen-wang.md#the-four-planes)), and the procedural
pixel path reads that map. A procedural biome with neither `<BitmapCaves>` nor
`bitmap_noise_file` gets a shared 1 x 1 dummy map, and so has no caves - only gradient and noise.

### Determinism

The carver (`0x00868f70`) uses a Lehmer (Park-Miller) generator:

```c
seed = seed * 16807 - (seed / 127773) * 2147483647;
if (seed < 1) seed += 2147483647;
```

It is seeded from the **world seed** (`0x01205004`): three values are drawn from a world-seeded
stream at load, and the third seeds both the carver and the wang-template path. Cave shapes are
therefore fully determined by the world seed.

### `CaveStructure`

Each `<CaveStructure>` inside `<structures>` stamps an authored image into the cave map.

| field | default |
|---|---|
| `image_file` | `""` |
| `count_min` / `count_max` | `50` / `100` |
| `aabb_min_x` / `aabb_min_y` | `50` / `100` |
| `aabb_max_x` / `aabb_max_y` | `50` / `100` |
| `strength_min` / `strength_max` | `1.5` / `1.5` |

The stamp (`0x00870250`) copies every non-empty plane of the image's wang map into the cave map
and also copies its spawn records, shifted to the stamp position (records that end up at a
negative coordinate are dropped). A structure therefore brings both its shape and its spawn
points.

`coalmine.xml` ships one: `data/biome_impl/coalmine/dangerroom.png`, 2-4 copies, strength
1.45-1.55, inside `5..507 x 0..230`. Structure images live in `data/biome_impl/<biome>/`.

## `FossilComponent`

A third way to place material: stamp an image made of one material.

| field | default |
|---|---|
| `count_min` | `0` |
| `count_max` | `0` |
| `seed` | `1` |
| `material` | `"bone"` |
| `image_file` | `""` |

These five are the only attributes it reads.

## Writing the cell

```c
if (material->cell_type == 3) {
    flat[(y - y0) * 512 + (x - x0)] = material->packed_value;   // no object
} else {
    pointer_grid[(row << 9) | col] = GridWorld::CreateCell(...); // 0x007048c0
}
```

Cell type 3 (`CellMaterial + 0x38`) is stored as a flat 4-byte value; `CreateCell` has no case for
it. Types 1, 2 and 4 allocate 0x40-, 0x3C- and 0x28-byte heap cells. This is why static terrain is
cheap and liquids, gases and fire are not.

The loop is skipped entirely when the chunk has no world-position key. A pixel whose cell slot is
already filled is left alone unless the chunk is being force-regenerated.

## Spawn requests

The per-pixel pass also collects where things should spawn, on a coarser grid. `0x0087d380` walks
the chunk in **10-pixel steps** and, at each sample:

- **wang biome:** reads the wang map's spawn plane. A non-zero entry is a request at
  `(tile_x * 10 - 5 - wang_offset_x, tile_y * 10 - 5 - wang_offset_y)`.
- **procedural biome:** reads the cave map's spawn plane and keeps the sample position.

Requests are stored in a de-duplicated set on the chunk (identical records are not added twice):

| field | meaning |
|---|---|
| x, y | position in pixels |
| width, height | in tiles: `1` for wang requests, `0` for procedural |
| mask | one byte from the wang map's mask plane |
| script | which spawn function to call |
| procedural flag | requires a nearby-space check before the call |
| biome | the biome whose `lua_script` is used |

The per-object pass then makes one Lua call per request:

```
<spawn function>(x, y, width * 10, height * 10, mask)
```

in the biome's `lua_script`. The vanilla scripts name the fifth argument `is_open_path`
(e.g. `spawn_small_enemies(x, y, w, h, is_open_path)`); most functions only use `x, y`. For procedural requests a rect query of radius `64` runs first and
the request is dropped if it finds nothing. This is where `spawn_items`, `spawn_wands`,
`spawn_orb`, `spawn_perk`, `load_pixel_scene` and the rest are called. Because the grid is 10 px,
one coloured template pixel can mean one call - large templates produce thousands of calls per
biome region.

A biome without `lua_script` logs `Warning - biome: <name> - doesn't have lua file...` and its
requests are dropped.

The record layout (0x20 bytes) is in
[worldgen-reference.md](worldgen-reference.md#the-0x20-byte-spawn-record).
